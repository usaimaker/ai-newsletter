AI Automation Daily - November 20, 2026

Today's theme: stop paying for tool-call round trips. This week the biggest savings are not about picking a smarter model - they are about how your agents call tools, which model does the routine work, and whether cached input is priced fairly. Five fresh, practical findings you can put to work today.

1. GPT-6.2 Astra & Sol: a cheaper flagship and 60% cheaper cached input

OpenAI shipped the GPT-6.2 family on Nov 18. Flagship Astra targets complex professional work (documents, coding, research, 3D design) and its API input and output prices dropped 20%, cached input fell 60%. OpenAI says Astra scores 5.5 points above Claude Fable 5.2 on Agents' Last Exam at about 5% of the cost. Daily-work model Sol finished within 0.5 points of Astra on FrontierCode 2.0 while using fewer tokens for multi-step workflows. Practical move: if your agent rereads the same context, the 60% cache cut is free savings - enable prompt caching and route routine multi-step jobs to Sol instead of the flagship.

2. Claude Code "Code Mode": up to 77% fewer tokens on tool-heavy jobs

Anthropic added an experimental Code Mode in Claude Code v2.1.323 (off by default). Instead of calling tools one by one, Claude writes a short JavaScript snippet that chains the calls locally and returns only the needed results. Third-party tests show API bills down 22-23% on multi-step tasks and cumulative tokens down 62-77% in tool-heavy runs, with built-in tool definitions cut from 16 to 3. It needs an environment variable and runs in a local terminal. One caveat: on simple file tasks Haiku 5.5 used 9% more tokens. Practical move: turn it on for workflows with many sequential tool calls, and A/B it on a simple task first.

3. Microsoft Ignite: MAI Code 2 at 40% of the cost, Decision 1.1 at 1/79

At Ignite 2026 Microsoft released seven models built to keep always-on agents affordable. MAI Code 2 reportedly reaches 98% of GPT-6.1 Sol's performance at about 40% of the cost, and 96% of Claude Opus 5.5 at 5% of the cost (Microsoft's own benchmarks, promotional pricing). The new Microsoft Decision 1.1 routing model is claimed to be 50x faster and about 1/79 the cost of GPT-6.1 Sol on decisions. Microsoft also said over 50 million agents have been registered in Agent 365. Practical move: put a cheap decision/routing model in front of the expensive one - let it classify and route, and only call the frontier model when the job truly needs it.

4. Tencent open-sources Hy4 flash: 1/20 the cost, and you can run it locally

On Nov 16 Tencent open-sourced Hy4 flash (plus FP8 and Base versions). API pricing is ¥0.5 per million input tokens and ¥2 output, with per-task cost claimed at 1/20 of the standard Hy4. It is built for document processing, slide generation, deep search and everyday office work. The weights are on GitHub, Hugging Face, ModelScope and GitCode, with a GGUF build on Hugging Face for local deployment. Practical move: for high-volume, repetitive office tasks, a sub-cent model or a local GGUF run removes most of the per-token bill - and local means no data leaves your machine.

5. Perplexity Multiagent: 16 agents cross-checking one another

Perplexity launched Multiagent on Nov 17 for its Computer platform. A lead agent (Claude Fable 5.2 in the example) splits connected work across up to 16 supporting agents running Claude Opus 5.5, GPT-6.1 Sol and Gemini 4 Carbon. Unlike the earlier Ultra tier, agents share evidence and flag conflicting figures before the lead assembles one answer - aimed at annual-report review, financial forecasts and deal diligence, with a human as final reviewer. Two cautions: it is web-only for Max subscribers (about $167/month), and Perplexity published no benchmark, error-rate or per-run point-cost data. Practical move: run one past job through Multiagent and Ultra side by side and compare what each flags against your human reviewer before trusting it.

Automation tip of the day: Attack the round trips, not just the model price. Use tool-chaining (Claude Code's Code Mode) so your agent stops paying for dozens of one-tool calls; put a cheap router or decision model in front of the expensive one; enable prompt caching so repeated context costs 60% less; and send high-volume, repetitive work to a sub-cent or local model. Then measure cost per completed task - that single number is the only proof your automation actually saves money.

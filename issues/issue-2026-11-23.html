AI Automation Daily - November 23, 2026

Today's theme: stop paying the model to do work a deterministic check or a local model can do for free. Five fresh findings, with the savings claims clearly separated from the verified numbers.

1. ZeroBurn targets the coding-agent token burn, not the model

Launched on Hacker News on Nov 22, ZeroBurn is an open-source coding-agent workflow toolkit from the team behind directly.social. It combines zero-token static and blast-radius checks, a local Ollama diff review, code-graph pre-fetching, parallel swarm file leases and one-line test receipts. Its headline claim is a 70-83% cut in cloud-token burn, with some self-reported tables as high as 98-99% on the publisher's own project. Practical move: the approach is the value, not the number. Clone it, run it on one repo, and measure your own burn before trusting the headline. Reserve paid frontier calls for work that actually benefits from them and keep routine checks deterministic.

2. Qwen4-Max adds a 1M-context price anchor at $1.50 per million

Alibaba released Qwen4-Max on Nov 16: a sparse mixture-of-experts model with 2.4 trillion total parameters, about 71 billion active per token and a one-million-token context. Vendor figures show 35% fewer tokens in high-effort mode and roughly 60% lower cost per task than its predecessor. Pricing is $1.50 in and $4.50 out per million, with cached input at $0.075. Practical move: for long-document and high-volume batch automation, this is a serious low-cost anchor. Price the completed task, not the token, and re-run any workflow you shelved last year for cost reasons.

3. Levenza brings personal admin agents into Teams and Slack

On Nov 23 Levenza announced global availability of personal AI agents that live inside Teams, Slack and Outlook. They proactively coordinate schedules, book rooms, liaise with travel agents, submit timesheets and work through a to-do list that picks up commitments from meetings, chats and email. Voice was added via its Fluid Inference acquisition, so you can brief the agent while commuting. Over 300 customers are live, and users report saving up to three hours a day on admin coordination. Practical move: admin scheduling is a concrete, low-risk first agent use case. Pilot one recurring workflow and measure hours returned before widening scope.

4. LTTS SDVault.ai cuts defect triage from four hours to ten minutes

L&T Technology Services launched SDVault.ai this week, running more than 250 domain-specific agents alongside deterministic, rule-based engineering logic. In early pilots, software-defect ticket triage fell from roughly four hours to ten minutes, and teams absorbed 30-40% more workload without adding staff. Final certification authority stays with humans, and the platform runs in customer-controlled cloud or on-premise environments to protect IP. Practical move: copy the pattern, not just the speed. Let agents accelerate the search and triage, keep deterministic rules for the safety-critical parts, and leave the final sign-off with a person.

5. Gemini API Tool Retrieval stops stuffing every prompt with tool schemas

Tool Retrieval entered preview in the Gemini API on Nov 19. Instead of loading every tool schema into every prompt, full schemas are fetched on demand inside the request, on Gemini 3.6 and newer, with no separate fee. Anthropic research published on Nov 16 points the same direction for memory: a few selective notes beat blanket recall in agent benchmarks. Practical move: on long-lived agents with large toolkits, move to on-demand tools and selective notes. It slashes prompt bloat and cost with no integration spend, and pairs well with cached input.

Automation tip of the day: audit the loop before you buy a bigger model

An agent workflow plans, calls tools, re-reads context and retries, so the bill comes from round trips, not raw tokens. Three moves that cost nothing: (1) strip the bloat - on-demand tool schemas and selective notes instead of fat prompts; (2) push routine checks and diffs to local models and deterministic tools, reserving frontier calls for the few steps that need them; (3) measure cost per completed task and set a per-run spend cap plus a kill switch so a retry loop cannot quietly drain the budget. Treat vendor savings figures as hypotheses to verify on your own workload.
